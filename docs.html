The definitive guide to Android automation.

Welcome to the GestureFlow ecosystem. You are now equipped with a professional-grade visual programming engine that transforms how you interact with your mobile device. From here, anything you can imagine on a screen, you can automate with absolute precision.

GestureFlow was born from a simple need: to make the power of coding accessible to everyone through a visual medium. We've eliminated the syntax errors and replaced them with a robust node-based canvas. This manual is your blueprint to mastering the engine, the interface, and the logic of high-performance automation. We will cover everything from the basic taps to complex data-aware logical loops that can interact with external APIs and Bluetooth hardware. Whether you are a professional tester, a productivity enthusiast, or a hardware tinkerer, GestureFlow has the tools you need to excel.

The Philosophy of Visual Flow

Traditional coding is powerful but slow and hard to learn. Screen macro recorders are fast but "dumb"—they can't react to changes. GestureFlow combines the speed of visual building with the intelligence of conditional logic. If data comes back from an API, the JSON node extracts the exact field you need. If a value needs to be reused later, the Text node stores it as a variable. This is automation that thinks, reacts, and persists through app updates and device restarts. Our mission is to put the full power of Android into your hands, without the complexity of traditional development.

Phase 1: High-Level System Setup

Unlike standard apps, GestureFlow operates as a privileged system component. This allows it to work globally—meaning it can interact with your Gmail, your favorite game, or your system settings with identical precision. This power requires two foundational "handshakes" with the Android OS. These permissions are strictly managed and do not involve any cloud-based data extraction or external reporting.

Standard Onboarding Sequence

1
Accessibility Service (The Core): This is the most critical permission. It grants the engine a "Virtual Hand" to perform gestures and a "Virtual Eye" to read screen text.
  • Open your phone's Settings app.
  • Search for Accessibility in the search bar.
  • Tap on Downloaded Apps (or Installed Services on older devices).
  • Select GestureFlow and toggle the switch to Enable.
  • Security Note: Android will show a standard warning. GestureFlow is designed with a "Local-Only" policy—it never uploads your screen data. All processing happens on-device and in real-time volatile memory.
2
Overlay Permission (The Layer): This is required for the application to "draw" its floating recording tools and status indicators on top of other apps. Without this, the recording bubble and the crosshair cannot function.
  • Go to Settings > Apps.
  • Find Special App Access (usually in the advanced menu or three-dot menu).
  • Select Display over other apps.
  • Locate GestureFlow in the list and grant the permission.
3
Notification Service: To keep you informed about long-running workflows or logic results, GestureFlow uses the system notification tray.

When you add your first Notification Node, the app will request access. Tap "Allow" to ensure status updates reach you even when the screen is locked. This is essential for workflows that run for several minutes or hours (like social media scroll-bots or web scrapers) to alert you upon completion or error.

Phase 2: Achieving 100% Reliability

The number one reason for automation failure on Android is "Battery Optimization." Android's system is designed to save power by killing apps it thinks are "idle." To the system, a background automation tool often looks idle, even when it's working hard to process logic every second. To achieve professional-grade stability, we must "harden" the app against these background killers.

⚠️ Mandatory Configuration

To ensure your workflows don't stop mid-way or skip nodes, you MUST exclude GestureFlow from battery restrictions. This ensures the Accessibility Service remains "Alive" and responsive in the background at all times.

  1. Long press the GestureFlow icon on your launcher home screen.
  2. Select App Info (usually indicated by an 'i' icon).
  3. Go to Battery (or Battery Usage).
  4. Select the "Unrestricted" (or No Restrictions) option. If you only see an "Optimize" toggle, ensure it is turned OFF.

Manufacturer-Specific Hardening Paths

Different phone brands have different "aggressive" cleaners and process managers. Follow these specific paths for your brand to ensure enterprise-grade stability. Failure to do this will result in the service being disconnected randomly by the OS.

ManufacturerThe "Secret" Setting & Path

Google Pixel Settings > Apps > See all apps > GestureFlow > Battery > Unrestricted. Pixel devices are generally the most stable once this single setting is changed.

The Design Canvas: Visual Logic Workspace

The Canvas is where "Drawing" meets "Programming." It is a 2D infinite workspace where you define the sequence of events that make up your pipeline. It uses a custom-built, hardware-accelerated rendering engine for smooth performance even with 100+ nodes and complex branching paths.

Navigating the Infinite Workspace

  • Panning (Moving): Use two fingers to drag the canvas in any direction. This allows you to follow long logical chains or move between different "clusters" of logic. Single-finger drag is reserved for moving individual nodes.
  • Zooming: Use the standard "pinch" gesture. Zoom out to see your whole architecture (0.2x) or zoom in to see specific node parameters and precise coordinate labels (3.0x). The engine handles auto-scaling of text for readability.
  • The "Fit to Content" Control: Tapping the center-focus icon at the bottom left will automatically calculate the best zoom level and translation to show every node on your screen at once. Essential for cleaning up "spaghetti" logic.
  • Canvas Locking: Tap the lock icon to freeze pan/zoom. This is highly recommended when you are drawing connections (edges) between nodes to avoid the canvas slipping while you aim for the ports.

The Handle & Connection (Port) System

Connecting nodes is how you define "What happens next." This is done through Handles—the circular ports on the sides of nodes. Execution always flows from right to left (out to in).

THEN Handle (Blue Port) The standard exit path. If a node completes (e.g., a Tap is performed), the engine follows this blue line to the next node. For conditions, this is the "True" path where text was found. This handle is located at the top-right of nodes.
ELSE Handle (Red Port) Found only on Logical nodes (Condition, Bluetooth Wait). This path is taken if the condition fails or times out. It is the secret to building "Smart" automation that retries, scrolls, or branches into different menus based on UI state.
Incoming Port (White Circle) Located on the left of every node. This is the "landing zone" for connections. Drop your dragged handle here to lock the link. A node can have unlimited incoming links but only one of each outgoing type.
Edge Deletion & Selection Tap on any existing connection line. A red "X" bubble will appear in the middle of the line—tap it to delete the connection. The line will also turn black to show it is currently selected. The engine uses smart routing to avoid node bodies.
💡 Start Node (#0): Look for the node with the pulsing green indicator. This is the root of your pipeline. You can change its type to anything (Tap, Delay, etc.), but it can never be deleted. Every workflow execution begins here. If you accidentally disconnect it, the workflow will stop immediately after Node #0 executes.

How the Logic Engine Thinks

GestureFlow doesn't just "play back" coordinates like a simple macro recorder. It uses a Reactive Execution Model that adapts to your phone's performance and UI state. This ensures that even if an app loads slightly slower today, your workflow remains robust and reliable.

Execution PhaseWhat the Engine is doing at the System Level
1. Snapshot Compilation The engine converts your visual nodes into a logical map. It identifies "Dead Ends" (nodes without connections) and prepares the memory map for runtime variables. It also checks for syntax errors in your variable tags (like missing closing braces).
2. Instruction Dispatch It sends a command to the system (e.g., "Tap at 500, 1000"). It waits for the Duration you set in the config before moving on. This duration acts as the "Hold" time for taps. Higher hold times can trigger "Context Menus" in some apps.
3. Inter-Step Sync There is a mandatory 300ms delay between every node. This ensures the Android OS has processed the previous tap and updated its internal state before the next command. This prevents "Input Lag" issues and skipped buttons.
4. Semantic UI Evaluation If it hits a Condition, it "scans" the whole screen. It looks at the text labels of every button, menu, and text view simultaneously using the Accessibility "Eye". This scan happens thousands of times per second until a match is found or timeout reached.
5. Infinite Loop Protection If your logic creates an infinite loop (A → B → A), the engine will automatically shut down after 500 visits to a single node to protect your battery and prevent system freezes. You will see a "Cycle Detected" error in the activity log.

Branching Logic: SUCCESS vs. ELSE

The "Else" handle (Red Port) is what makes GestureFlow powerful. It allows you to build workflows that don't just fail when something goes wrong—they adapt and react. This is how you build "Human-like" intelligence into your device automation.

Advanced Looping Pattern: The Smart Waiter

The most common logic pattern is the Retry Loop. This is essential for apps that have inconsistent loading times or network-dependent UI. It eliminates the need for long, hard-coded delays.

[Condition: Look for "Dashboard"] -- (Found) --> [Tap: Profile] -- (Not Found) --> [Delay: 2000ms] --> [Back to Condition]

In this pattern, the workflow will patiently wait for the "Dashboard" text to appear, checking every two seconds, and only proceeding once the UI is actually ready. This is significantly more reliable than a fixed 10-second wait, as it proceeds the instant the app is ready.

Memory & Dynamic Variables

Variables are the "short-term memory" of your workflow. They allow data to flow dynamically from one node to another. All variables are case-sensitive and exist only while the specific workflow is running. This prevents data from one workflow from leaking into another, ensuring enterprise-grade data isolation and security.

Storing Data Points

Data is stored using Text, API, JSON, or Bluetooth Receive nodes. You assign a name, like current_user. We recommend using snake_case for clarity and to avoid conflicts with system labels. Variables can store numbers, text, or even whole JSON objects from APIs.

The Variable Tag Syntax: ${name}

To use a stored value in any text field (like a Notification message, an API URL, or a Text value), wrap the variable name in curly braces and a dollar sign. The engine will look up the value at the exact microsecond that node is reached.

// Example of String Interpolation: If variable 'status' contains "Success", your Notification node can say: "Task finished with status: ${status}" // Example in API URL: https://api.test.com/get_user?id=${user_id}
⚠️ Variable Fallback Logic: If you use a variable that hasn't been set yet (e.g. ${missing_val}), the engine will output the literal text "${missing_val}". Always ensure your Text or JSON nodes happen before you use the variable in the logical sequence. Check your activity log to see variable assignments in real-time.

Pro Best Practices for Automation

Follow these rules used by professional automation architects to ensure 100% success rates even on low-end devices, varying network conditions, or different screen sizes. Stability is the most important part of automation.

The Animation Buffer Rule Modern apps use animations (fade-in, slide-up, shared element transitions) that take about 300-500ms. If you tap during the animation, the app will ignore the touch. Always add a 500ms Delay after any click that changes the screen state. This is the #1 fix for "skipped" steps.
Coordinate Consistency Rule Pixel coordinates can change if you rotate your screen, adjust display scaling, or switch phone models. Record and run flows in the same orientation, and keep display settings stable when sharing workflow JSON.
Smart Wait-Then-Act Pattern Instead of guessing how long a page takes to load (which varies on Wi-Fi vs LTE), use a **Condition Node** searching for a unique word on the new page. Connect the Success handle to your next action. This is the most robust method for any automation.
Descriptive Pipeline Labeling Rename your pipelines clearly. Instead of "Workflow_1," use "Daily_Expense_Uploader". This makes the Activity Log on the Home screen much easier to read and debug. You can rename a flow by tapping its title at the top of the Canvas.

Security, Privacy & Data Boundaries

Because GestureFlow uses the Accessibility API, we hold ourselves to the highest possible security standards. We operate on a **Zero-Leak, Local-Only** architecture. Your security is our primary design constraint, and we build everything with "Privacy-by-Default". We do not even require an account or email to use the app.

🔒 The "Zero-Leak" Policy: We do not have a server. We do not have a cloud. We do not have a database outside your phone. Your data is literally impossible for us to see, even if we wanted to. We never request the "Internet" permission except for YOUR API nodes.

The Data Boundary Map

  • Screen Data Processing: The engine "looks" at your screen ONLY when a workflow is active or you are recording. This data is processed in volatile memory (RAM) and is wiped the microsecond the logical check is complete. It is never saved to a log or a permanent file. We do not record video of your screen.
  • Workflow Data Storage: Your nodes, logic, and variables are stored in a private, encrypted database on your device (/data/user/0/com.pankajkumarrout.gestureflow/databases/). This folder is inaccessible to other apps on your phone even if they have broad storage permissions.
  • Third-Party Tracking: GestureFlow contains NO analytics SDKs (no Firebase, no Mixpanel, no Adjust, no Facebook SDK). We do not track your device ID, your IP address, or your automation habits. We value your anonymity as much as you do. We don't even use Crashlytics.
  • Network Transparency: The app only uses the Internet if YOU explicitly create an API Node. You have full control over where data is sent, what payload is transmitted, and what headers are used. Your tokens are your own.

The Ultimate Troubleshooting Guide

If your automation is stuck or behaving erratically, check these common "gotchas" before reaching out for support. 99% of issues are related to system configuration rather than engine errors.

Issue ObservedLikely Root CauseProven Solution
Taps miss the target button Display scaling or font size too large. Device rotation. Reset Android Display settings to default. Ensure the target app is in the same orientation as when recorded.
Workflow stops mid-run without error Android battery optimization killing background service. Device auto-lock. Set app to "Unrestricted" in App Info > Battery. Keep the screen ON during execution.
Conditions never match (False) Case sensitivity or hidden zero-width spaces. Timeout too short. Double check exact text. "Login" is not the same as "LOGIN". Increase Wait Time to 5000ms if network is slow.

"Cycle Detected" Termination Infinite loop in your logic connections. Check your Red/Blue lines. Ensure you aren't looping indefinitely without an exit condition. Check for recursive loops.

Glossary of Core Terms

Pipeline / Workflow

The container for your automation logic. A pipeline consists of multiple nodes connected together to perform a complete task (e.g., "Auto-check weather and alert"). You can have unlimited pipelines in your personal library. Pipelines can be shared as JSON.

Node

A single building block of logic (e.g., a Tap, a Delay, or an API call). Each node performs exactly one task and has its own configuration parameters. Nodes can be dragged and rearranged freely on the infinite canvas.

Edge / Connection

The line connecting two nodes, representing the flow of execution. Blue lines represent SUCCESS; Red lines represent ELSE/FAILURE paths. The flow direction is indicated by the line's origin handle.

Accessibility Service

The core Android component that allows GestureFlow to interact with other apps. It must be manually enabled in your phone's security settings for any automation to function. It acts as the "Brain" and "Hands" of the app.

Interpolation

The process of injecting a variable's value into a text field using the ${name} syntax at runtime. E.g. "Price is ${price}" becomes "Price is $5.00" when processed by the engine.

JSON Path

A dot-based selector used by the JSON node to extract nested response data, such as data.name or user.profile.email.

FAQ (Frequently Asked Questions)

Can I automate Instagram, TikTok, or WhatsApp?

Yes. GestureFlow works on any app that uses standard Android UI components. You can automate liking, scrolling, and even sending messages. However, be aware that many social apps have bot detection that might flag repetitive identical gestures if you don't add random delays (jitter) between actions. We recommend keeping flows "human-like."

Is this app a virus? My phone gave a warning.

No. Android gives a standard "Strong Warning" to all apps that request Accessibility Services because those services are very powerful. GestureFlow is safe because it is local-only and has no cloud component to leak your data. You can verify this in the app's permission settings and by using any network monitor tool.

Can I share my workflows with friends?

Absolutely. Use the Export feature on the canvas to get a JSON string. Your friends can then use the Import icon on the Home Hub to paste your code. This is the fastest way to collaborate on complex scripts and build a community library of automation. We encourage sharing on GitHub!

Does it work with the screen off?

No. For security reasons, Android requires an active UI session for gestures to be performed. The screen must be ON and the device UNLOCKED for the engine to simulate human touch. You can use the "Keep Screen On" settings or developer options to help with long runs.

What is the "500 visit" limit?

This is a safety circuit breaker. If the engine detects it has visited the same node 500 times in a single execution session, it assumes you've created an infinite loop by mistake and kills the workflow to save your battery from draining completely and to prevent system overheating.
